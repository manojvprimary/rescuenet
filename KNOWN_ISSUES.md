# Known Issues

Status as of the `v0.1.0-baseline` tag (2026-10-03). Risks and mitigations live in [`docs/RISK_LOG.md`](docs/RISK_LOG.md); this file lists defects and gaps a new reader should know about before running anything.

| ID | Issue | Impact | Planned fix |
|----|-------|--------|-------------|
| KI-01 | **Updated 2026-10-21:** v2 is now deployed behind `WEIGHTING_MODE` (default `llm`) and measured on the deployed pipeline (13 cases, see ENGINEERING_LOG Week 7); the default has not been promoted. **Earlier (2026-10-11):** the weights module is now wired into `needs-profile` behind `WEIGHTING_MODE` (default `llm`), tested with Bedrock mocked and run live against 7 cases; **nothing is deployed**, so the live system still asks Bedrock to invent the five weights per case (no temperature set). | The v2 path exists in code and evidence only. | Weeks 5-6, behind a `WEIGHTING_MODE` flag. |
| KI-02 | **Updated 2026-10-11:** `ahp-weights.json` now holds v1 vectors built from 30 judgments that were **proposed by the AI assistant from five cited sources and adopted by the student** (single judge; all CR < 0.10). The sources support direction, not magnitude. | Magnitudes (the 1-9 sizes) are the weakest part of the weights; the sensitivity check is the safeguard. | Revisit with the second judge / supervisor input at the midpoint (issue #2). |
| KI-03 | The species-match fix is in the repo but **not deployed**. | The live arbitrator still has the old existence check. | Deploy after the non-production latency/error-rate run. |
| KI-04 | No tests exist for `needs-profile`, the arbitrator's DynamoDB flow, or any other Lambda; the 36 tests cover only the new pure modules. | Most of the pipeline has no automated tests. | The evaluation harness (Weeks 5-7) replays cases through the scoring path. |
| KI-05 | Local default Node is 25.9; Lambda is 20.x. `npm install` on 25.9 prints an engine warning. | A test could pass here and differ in production. | **Verified under Node 20.20.2** on 2026-10-04 (install, type-check, 36 tests, smoke all pass; `docs/evidence/sprint-1/node20-output.txt`). Remaining: make Node 20 the local default (nvm or Homebrew) so day-to-day runs match production. |
| KI-06 | `npm run synth` and the deployment need AWS credentials and a bootstrapped account; they were not run against a clean machine. | A peer without AWS cannot run the synth step. | Tests and smoke test need no AWS; synth is marked optional in the README. |
| KI-07 | `rescuenet-needs` table and `caseId-index` GSI are provisioned but unused. | Dead infrastructure. | Deferred (out of scope). |
| KI-08 | Geocoding falls back to raw coordinates (no Place Index). | Case addresses are coordinates. | Out of scope; issue #3. |
| KI-09 | The hand-picked normalization constants and freshness table are uncalibrated. | They may dominate rankings regardless of weights. | Out of scope; the harness logs the decisive factor per case. |
| KI-10 | `cdk.json` runs the app through `npx ts-node`; `ts-node` is now pinned, but `npm run synth` was verified only on the author's machine. | Reproducibility on other machines is unconfirmed. | A peer clone test (see the sprint reflection). |
| KI-11 | **Tested 2026-10-25 (Hard Stop 4 ablation):** counting capacity once raises correct winners from 7 to 9-10 of 12 when weights are case-specific and changes nothing with equal weights; under the production formula all four weighting methods tie at 7 of 12. Original finding: **the arbitrator's scoring formula limits the results, independent of the weights.** `pickup_urgency` and `long_term_care` are both computed from the shelter's open slots, so capacity is counted twice; no term measures the case's own urgency. Even v1's live per-case weights match only 3 of 6 annotated cases, the same 3 as v2 by raw score. | A shelter with more slots can beat a nearer one in an injured-animal case (SYN-01). | Not changed (R-07 accepted this term). Raised for the midpoint adjustment memo. |
| KI-12 | **The near-tie rule (margin < 0.02, smaller shelterId wins) is arbitrary and, in these fixtures, correlates with the annotations.** It decided SYN-04 and SYN-05 in v2's favour; by raw score both are won by shelter-C. | The headline 5 of 6 depends on the rule; by raw score v2 = v1 = 3 of 6. | Both numbers are reported; the raw-score metric was added after seeing the first results and is labelled as such. |
| KI-13 | **The classifier's probabilities are near one-hot** (mostly 0 or 1; only SYN-07 is a real mix), so `blend` behaves almost like `top` on this sample. | The blend's main design advantage (continuous weights) is barely exercised. | Reported as a limitation; revisit the prompt or add calibration at the midpoint. |
| KI-14 | **SYN-07 and SYN-05 do not really test ranking:** the `has_vet` hard constraint leaves one (SYN-07) or two (SYN-05) eligible shelters. | Their "correct" results say little about the weights. | Disclosed; add cases where the vet constraint does not decide. |
| KI-15 | `npm audit` reports 37 advisories (1 critical, 30 high), all in the Jest toolchain except one high in a bundled `aws-cdk-lib` dependency (`brace-expansion`). | Test-time tooling only; nothing here is deployed or user-facing. | Left as is this sprint; revisit before Hard Stop 5 (hardening). |
| KI-16 | The evaluation set has 8 synthetic cases and **no real case** (the earlier plan counted 1 real + 8 synthetic = 9). Annotations were written by one person and transcribed from the Hard Stop 2 matrix. | Every count is out of 6-8 and directional only. | Real case to be added with PII review; second annotator still sought (R-03). |
| KI-17 | The seeded shelter roster has one dominant shelter (Manhattan Animal Care Center: most slots, vet on site, widest radius): it won all 13 measured cases in both modes. | Live runs cannot discriminate between weighting methods; the demo understates routing differences. | Add roster variants or synthetic bids to the live path before drawing routing conclusions (Week 8). |
| KI-18 | The Week 7 measurement ran in the only deployed account (demo data, no real users), not an isolated environment, and every block began on cold, freshly reconfigured functions. | Latency figures are indicative; they are not a production benchmark. | Isolated stack or alias with a warm-up pass before Hard Stop 5. |
| KI-19 | Five test cases from an aborted measurement run, and ~12 other demo cases, remain in the cases table and generated Slack posts in the tier-2 channels. | Test noise only; cases expire by TTL. | None needed; noted so nobody mistakes them for real reports. |
| KI-20 | Set-2 evaluation cases and annotations (SYN-09 to SYN-16) were written by the AI assistant, aimed at the same trade-offs the formula variants F1 to F3 address; the student approved them but did not author them, and there is still one annotator. | The improvement under F1 to F3 may be partly circular; set 1 (annotated by the student before any variant existed) shows a smaller but same-direction gain. | Independent annotator and expert-proposed variants (B-03). |
| KI-21 | Fixture SYN-04 includes a zero-slot shelter bid, which the tier-1 agent never submits in production (`No available slots`). Under capacity-once formulas that bid wins. | Overstates the failure; a post-hoc variant without such bids is reported separately and labelled. | Fixture left as written (pre-registered); note carried in every report. |
| KI-22 | Open capacity is a score term, not a hard constraint, in the arbitrator: the double-counted capacity term currently acts as an accidental guard against empty shelters. | If the formula is corrected without adding a minimum-capacity constraint, an empty shelter could win. | Add `availableSlots > 0` as an eligibility rule alongside any formula change. |
| KI-23 | **Injury detection in the rule-based paths reads only the photo analysis** (`image.injuryIndicators`), not the free-text report: the v2 fallback hard constraints, the rule-based comparison classifier, the v1 default profile, and the ablation's fixed constraints. A text-only report ("bleeding, can't stand") gets no `has_vet` requirement on those paths. Raised in the student's code review. The live LLM paths do read the text. | A failed classifier can under-protect an injured animal reported by text. No effect on the ablation results (every set-1 and set-2 injured fixture carries photo indicators). | Read injuries from `condition` and `reporterSituation` as well; add tests for text-only reports (B-14). |
| KI-24 | No concept of a **temporary or emergency shelter role**: a shelter that does not normally take a species cannot offer to stabilize or hold an animal until a suitable shelter confirms. Idea from the student's code review. | An injured animal of a species no nearby shelter accepts is escalated rather than stabilized. | Design question for a later term; not in the current scope. |
